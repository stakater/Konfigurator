Guidance for working in this repository. Rasheed's global `~/.claude/CLAUDE.md` applies too.
This file adds the repo specifics and **wins on conflict**.

## What this is

**Konfigurator** is a Kubernetes operator (kubebuilder v3 layout, controller-runtime) that
renders **Go templates against live cluster state** (Pods, Services, Ingresses) into a
**ConfigMap or Secret**, then mounts the result into a target Deployment, DaemonSet, or
StatefulSet. The canonical use case is generating fluentd config per pod (`examples/`).

- Module `github.com/stakater/konfigurator` · API group `konfigurator.stakater.com/v1alpha1`
- CRDs:
  - **`KonfiguratorTemplate`**: the main feature.
  - **`PodMetadataInjector`**: injects annotations into pods *in the render context only*. It
    never patches real pods.
- Stack: **Go 1.27.4 · controller-runtime v0.25 · k8s libs v0.37** (upgraded in H.7).
  **Minimum cluster: Kubernetes 1.30 / OpenShift 4.17** (CRD validation ratcheting; chart
  `kubeVersion`). User-visible changes go in `CHANGELOG.md` → *Unreleased*, with upgrade notes. Legacy
  upstream project (last functional work in 2021). **It is being hardened before new feature
  work.** See `docs/reviews/2026-11-17-baseline-review.md`
  and roadmap Epic H.

## Mental model (how it actually works today)

```
Pod/Service/Ingress reconcilers ──► in-memory xContext.Context (shared slices, NO lock)
PodMetadataInjector reconciler  ──┘        │
                                           ▼
KonfiguratorTemplate reconciler (timer: spec.updateFrequency min, default 2m)
   → render spec.templates (text/template + pkg/template/funcs)
   → optional POST to spec.validationWebhookURL
   → CreateOrUpdate ConfigMap/Secret "konfigurator-<app>-rendered"
   → patch app's pod template: add volume + volumeMounts
   → finalizer: on delete, unmount + delete rendered object
```

| Path | What it is |
|---|---|
| `main.go` | Composition root: builds the manager and wires all 5 reconcilers to **one shared `xContext.Context`** |
| `controllers/` | Reconcilers. `konfiguratortemplate_controller.go` is the core; pod/service/ingress controllers only maintain the context mirror |
| `pkg/context` | The shared render-context struct (plain slices) |
| `pkg/template`, `pkg/template/funcs` | Template execution + func map (docker-gen/kubegen-style helpers) |
| `pkg/kube/mounts` | Adds/removes the volume + mounts on the target workload via reflection (`fatih/structs`) |
| `pkg/kube/factory.go` | `app.kind` → fresh typed object, or an error for unknown kinds (fixed in H.1) |
| `api/v1alpha1` | CRD Go types; `zz_generated.deepcopy.go` is generated |
| `config/` | kustomize manifests (CRDs generated by controller-gen) |
| `charts/konfigurator` | Helm chart (the shipped install path). Its `crd.yaml` is a copy of the generated CRDs |

## Known traps (read before touching the code)

These are documented in the baseline review. Don't "fix" them in passing. Each one belongs to
a roadmap story.

- **The render context is a hand-rolled, unlocked mirror of the informer cache** (B2). Deleted
  objects are never evicted (B1). The planned fix is to *delete* it and `List` from the
  manager cache (H.5). **Don't add more state to `xContext.Context`.**
- Errors are classified **at the source** with `pkg/reconcileerr.Permanent` (template parse,
  webhook not allow-listed/denied, container missing, invalid spec) and mapped once in
  `controllers.fail()`: permanent → `reconcile.TerminalError` (logged, counted, **not**
  requeued); anything else → returned for backoff. Don't call operator-utils `ManageError` in
  this controller: it swallows errors. Nothing lands in `.status` yet (B4/H.6).
- ~~An unknown `app.kind` causes a nil-interface panic and a crash-loop (B3).~~ Fixed in H.1
  (CRD enums + `IsValid` + `RecoverPanic`). Keep it that way: every user-supplied field gets a
  validation marker.
- Templates in cluster-wide mode can read **every namespace's** pod specs (S1). ~~The webhook is
  an unbounded `http.Post` to a user-supplied URL (S2).~~ Fixed in H.2 (`pkg/webhook`, admin
  allow-list). Treat any change near rendering or the webhook as security-sensitive.
- **Never dispatch on `TypeMeta`/GVK of typed objects.** controller-runtime clears TypeMeta
  after a typed `Get`. Use a Go type switch instead (H.7 regression, `pkg/kube/lists`).
- `PodMetadataInjector` reads the CR's **metadata** labels/annotations. `spec.selector` and
  `spec.objectMeta` are dead (B9, awaiting a decision).

## Invariants (target state; new code must move toward these, never away)

1. **Tenant isolation:** a template sees and writes only what its namespace may. Any
   cross-namespace visibility is an explicit admin opt-in in operator config, never in the CR.
2. **The render context comes from the informer cache.** No parallel mirrors, no unsynced
   reads.
3. **No panics on user input.** The CRD schema validates (enums/minimums), and the controller
   returns errors.
4. **Outbound calls are bounded:** timeout, size cap, `ctx`, an admin allow-list.
5. **Least privilege:** chart RBAC matches the watch mode. The operator never adopts objects it
   didn't create.
6. **Observable:** failures show in `.status.conditions`, and transient errors requeue.

## Method: how work happens here

The full loop is in **`docs/method.md`**. It's ported from kube-ward, which took the useful
parts of BMAD v6: the context-capsule planning doc and the approval gate. In order:

1. **Story** in `docs/roadmap.md`: *As a … I want … so that …* + a **Done:** line. It starts
   as 📝 Draft.
2. **Approval.** Nothing moves Draft → 🔨 without Rasheed's explicit 👍.
3. **Planning doc** `docs/planning/<code>-<slug>.md`, copied from `TEMPLATE.md`. Commit it
   before code.
4. **TDD:** red first, table-driven, with the controller-runtime **fake client** at the seams
   (envtest/kind e2e where the fake can't tell; see H.7).
5. **DoD:** `make verify` green. Story marked ✅ with its plan linked. Review finding id
   closed. Commit + push on a feature branch.

Decisions with lasting consequences get an ADR in `docs/adr/` (immutable once accepted;
supersede, never edit).

## Definition of Done: `make verify`

`make verify` runs **vet · build · lint (golangci-lint v2, `.golangci.yml`; formatting is
enforced here via gofmt/goimports) · `go test -race`**. CI also runs `make codegen-check vulncheck` and an e2e job (`make e2e`). A Claude Code **PostToolUse hook** (`.claude/settings.json` →
`hack/verify-hook.sh`) runs it after every `*.go`/`go.mod`/`go.sum` edit. It is committed on
purpose (same as kube-ward): the hook is how the DoD is enforced in agent sessions. To opt out
locally, set `"disableAllHooks": true` in `.claude/settings.local.json`. Don't report work
done without seeing it green.

Other targets (`make help` lists all of them). Tools are **pinned in the Makefile** and
installed with `go install` into the gitignored `./bin`:
- `make generate manifests`: regenerate deepcopy, CRDs, and RBAC from markers. `manifests`
  also syncs the chart's CRD copy (`chart-crds`). **Never hand-edit generated files.**
  `make codegen-check` fails on drift.
- `make vulncheck`: govulncheck. It must report 0, or the PR says why.
- `make e2e`: kind cluster, real image, real chart, render/mount/reject/cleanup smoke test.
  Use `KEEP_CLUSTER=1` to debug. Needs docker, kubectl, and helm.
- `make helm-lint`.
- Upgrading Go: `go.mod`, the Dockerfile builder image, and `GOLANG_VERSION` in all three
  workflows move together. Always use a supported Go (one of the two newest minors).
  k8s libs, controller-runtime, and controller-tools move as a set, and need a green
  `make e2e`.

## Testing conventions

- **Table-driven** by default. Unit tests never touch a real cluster or network. Use the fake
  client (`sigs.k8s.io/controller-runtime/pkg/client/fake`) and `pkg/kube/testutil`.
- Every bug fix starts with a test that reproduces the bug.
- **Every reconciler failure point has a row in `TestReconcileFailureClassification`** (injected
  fault → terminal or retry). `make mutation-check` swallows each error site in turn and requires
  a test to fail; it runs in CI. If you add an error return, add the row, then run it. The review lists which paths have
  no tests: NotFound/delete, unknown kind, Secret key removal, concurrency, webhook failure.
- Startup wiring is code too. If you change `main.go` wiring, a test must build it through the
  same function the binary uses.

## Conventions

- Go: `gofmt`, wrapped errors (`fmt.Errorf("…: %w", err)`), use the reconcile `ctx`. Never
  store request-scoped state on the reconciler struct.
- API changes: `+kubebuilder:validation` markers (enum/minimum/required) on every
  user-supplied field. Regenerate, then copy the CRD into the chart.
- Chart and code move together. A new permission means a `+kubebuilder:rbac` marker **and** a
  chart RBAC change.
- Feature branch per story, never `master`. Commit messages say what + why and cite the story
  code / finding id.
